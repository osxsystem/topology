# Research: portable adapt-generated settings.json (#50 + #51)

- **Date:** 2026-06-13
- **Feature slug:** adapt-portable-settings
- **Issues:** [#50](https://github.com/osxsystem/topology/issues/50) (portable hook paths, bug), [#51](https://github.com/osxsystem/topology/issues/51) (stop pinning GATEKEEPER_BIN, bug)

## Symptom (the bug to reproduce)

The dogfood `.claude/settings.json` is generated by `gatekeeper adapt` with **absolute, clone-specific**
paths. When the clone/worktree that generated it is deleted (normal phase-worktree cleanup), every later
session in any other clone fires `PreToolUse:Bash hook error … /…/topology-phase12/hooks/security-scan.sh:
No such file or directory`, and a stale `GATEKEEPER_BIN` makes `gatekeeper doctor` exit 1 (forcing an
`env -u GATEKEEPER_BIN` workaround). Recorded in memory `dogfood-settings-pinned-to-worktree`.

## How adapt builds settings today

`cmd_adapt(args, read_root, write_root)` — `adapt.rs:745`:
- **`read_root`** = framework/payload root: where `hooks/`, `AGENTS.md`, `skills/`, and `bin/gatekeeper`
  live. (`adapt.rs:831` `build_claude_hooks(read_root)`; `adapt.rs:838` `bin = read_root/bin/gatekeeper`.)
- **`write_root`** = project root = `$CLAUDE_PROJECT_DIR`: where `.claude/settings.json` is written
  (`adapt.rs:843`).
- **`read_root == write_root` ⟺ in-framework / dogfood**; they differ ⟺ governed downstream project
  (framework installed elsewhere). The code already computes `roots_differ` at `adapt.rs:817`.

`build_claude_hooks` (`adapt.rs:515`) emits hook `command` = `read_root.join("hooks/<name>.sh")` —
absolute. `merge_claude_settings` (`adapt.rs:155`) always sets `env.GATEKEEPER_BIN = bin` (absolute).

## Two facts that shape the fix

1. **`${CLAUDE_PROJECT_DIR}` expansion is location-dependent** (verified against Claude Code docs,
   2026-06-13): it **expands** in hook `command` strings (config-level substitution; the documented,
   recommended portability mechanism) but **does NOT** expand in the settings `env` block (literal
   strings). So the hook half is fixable in-place; the `GATEKEEPER_BIN` half is not — it must be dropped
   or resolved differently.

2. **In dogfood, `GATEKEEPER_BIN` is already dead-on-arrival.** The pinned value is
   `read_root/bin/gatekeeper`, but the dev clone has **no `bin/gatekeeper`** (confirmed: `ls bin/gatekeeper`
   → not found; the real build is `gatekeeper/target/release/gatekeeper`). The hook's tier-1 check
   (`hooks/security-scan.sh:33`, `[[ -n GATEKEEPER_BIN && -x GATEKEEPER_BIN ]]`) fails and falls through
   to tier 4 (`$ROOT/gatekeeper/target/release/gatekeeper`). So the pin is **redundant and fragile** in
   the roots-equal case — dropping it is strictly safe there.

The hook script already resolves the binary via a 6-tier fallback (`security-scan.sh:14-19`):
`$GATEKEEPER_BIN` → `$ROOT/bin/gatekeeper` → `$CLAUDE_PLUGIN_DATA/bin/gatekeeper` →
`$ROOT/gatekeeper/target/release/gatekeeper` → `…/target/debug/gatekeeper` → `gatekeeper` on PATH.

## Governed projects must NOT regress

`CONTRACT.md`: *"In governed projects, `gatekeeper` resolves through the `GATEKEEPER_BIN` environment
variable wired in `.claude/settings.json`."* When the payload is installed **outside** the project
(`read_root` ≠ `write_root`), the absolute hook path and the pinned absolute `GATEKEEPER_BIN` are the
correct resolution mechanism — `${CLAUDE_PROJECT_DIR}` would point at the wrong tree. Any fix must
preserve roots-differ behavior unchanged.

## Existing tests (the safety net + the gap)

- `cli_adapt.rs::adapt_writes_to_project_not_framework` (line 172) — **governed** (fw ≠ proj); asserts
  hook paths point at the framework dir. Must keep passing.
- `cli_adapt.rs::ac4_settings_no_clobber` (509), `ac5_gatekeeper_bin_value` (553) — **governed**
  (`scratch_fw_with_template` + `scratch_proj`); assert `GATEKEEPER_BIN == <fw>/bin/gatekeeper`. Must
  keep passing — my change only touches the roots-equal branch.
- `cli_adapt.rs::claude_writes_hook_settings` (100) and `adapt.rs:1095` — loose `contains("…sh")`; still
  true with a `${CLAUDE_PROJECT_DIR}/`-prefixed path.
- **Gap:** there is no test for the roots-equal (dogfood) settings shape. That is the new TDD target.

## Scope

`adapt.rs` is **not** a protected path, so editing it needs no override. But adapt *writes*
`.claude/settings.json` (a protected path) — the generated output must still pass `gatekeeper scan`.
Pure-Rust change; no new deps; three-language-lanes preserved (enforcement stays in Rust).
