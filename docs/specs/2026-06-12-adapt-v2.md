## Goal

One `gatekeeper adapt` run in a governed project delivers everything the project needs to run under
Topology: the artifact scaffold, the resolved binary wired so `gatekeeper` works with no PATH/sudo,
and the operating **contract** injected into the harness's native always-on surface — **append-only,
never clobbering user content**, and **idempotent** (a second run is a no-op; `--check` reports
drift without writing).

## 1. New delivery primitives (`adapt.rs`)

The whole-file `GenFile` / `apply_or_check` path is **kept unchanged** for adapt-owned files. Two
*partial-file* editors are added for user-owned files, each pure over (existing_content, payload)
returning the new content + a verdict, so they are unit-testable and reuse the 0/1/2 exit contract.

### 1a. `ensure_import_line(existing: Option<&str>, line: &str) -> Edit`
- `existing = None` (file missing) → create with exactly `line` + `\n`.
- `line` already present (exact, trimmed, any position) → **no-op** (`Unchanged`).
- otherwise → append `line` on its own line, preserving prior content and a single trailing newline.
- `--check`: present → `0`; absent/missing → `1` (prints `MISSING-IMPORT <file>`); never writes.

### 1b. `ensure_managed_block(existing: Option<&str>, body: &str) -> Edit`
- Markers: `<!-- BEGIN TOPOLOGY MANAGED BLOCK -->` … `<!-- END TOPOLOGY MANAGED BLOCK -->`.
- No block present → append the marker-wrapped `body` (create file if missing), preserving prior
  content.
- Block present, byte-identical body → `Unchanged`. Present but different → **replace in place**
  (content outside the markers untouched).
- Malformed (begin without end, or duplicate begin) → **error** (exit `2`), naming the file — never
  guess where the block ends.
- `--check`: `Unchanged` → `0`; would-create or would-replace → `1` (`DRIFT-BLOCK <file>`); never
  writes.

`Edit` enum: `Unchanged | Created(String) | Updated(String) | Failed(String)`. A small
`apply_edits(edits, check)` mirrors `apply_or_check` for these partial files (write or check), with
the same exit-code aggregation (any `1` → 1; any `Failed` → 2).

## 2. `GATEKEEPER_BIN` via settings.json merge (resolves research M1)

`build_claude` stops emitting a whole-file `settings.json`. Instead a new merge step:
- Read existing `<project>/.claude/settings.json` as `serde_json::Value` (object), or `{}` if absent
  / `null`. A non-object existing file → error (exit `2`, "not a JSON object"); do not clobber.
- Set `obj["hooks"]` = the generated hook wiring (adapt-owned, replaced wholesale).
- Ensure `obj["env"]` is an object; set `obj["env"]["GATEKEEPER_BIN"]` =
  `<read_root>/bin/gatekeeper`. **Other `env` keys and all other top-level keys are preserved.**
- Serialize pretty + trailing `\n`; write (or `--check`: compare *only* that `hooks` equals and
  `env.GATEKEEPER_BIN` equals — extra user keys are not drift).

This merge is a pure function `merge_claude_settings(existing: Option<Value>, hooks: Value, bin: &str)
-> Result<Value, String>` so the preservation property is unit-tested directly.

## 3. Scaffold + contract write (the project-install path)

In `cmd_adapt`'s **roots-differ branch** (after the existing `build_project_config`), when not in a
print-only `--contract` invocation:
1. Scaffold `.claude/topology/{research,specs,plans,verify,reviews}/.gitkeep` (whole-file GenFiles,
   empty content; idempotent under `apply_or_check`).
2. Render the contract once via `render_contract(template, project_ctx())` and write it to
   `<project>/.topology/CONTRACT.md` as an adapt-owned `GenFile` (it lives in the payload dir, the
   user does not edit it — whole-file ownership is correct here).
3. For `--harness claude`: `ensure_import_line(CLAUDE.md, "@.topology/CONTRACT.md")`.
   For `--harness codex`: `ensure_managed_block(AGENTS.md, <import-equivalent pointer to the
   contract>)` — codex has no `@import`, so the managed block carries the contract pointer text
   (a one-line directive to read `.topology/CONTRACT.md`, kept short; the body itself stays in the
   payload file so upgrades touch only the payload).
4. cursor / opencode: unchanged from v1 in this PR (see §0).

Hook wiring and `read_root != write_root` semantics are otherwise as today.

## 4. Bare-stub first-session instruction (resolves research Q5)

`templates/CONTRACT.template.md` gains a short, gate-shaped section near the top:

> **First session in a new project.** If the project documentation above this import line is a bare
> Topology stub (no project-specific content), your first gate is: analyze the codebase, write the
> project's own documentation above the import, *then* proceed through the gate sequence.

This is portable text (no new placeholder), so it renders identically for framework and project; in
the framework repo it's a harmless no-op (the doc above is already written). The
`render_contract` fail-closed property and the existing AGENTS.md byte-equality test (Phase 10)
both continue to hold — the new section is inside the template, so the framework `AGENTS.md` is
regenerated to include it in the same PR.

## 5. CLI surface

No new subcommand. `gatekeeper adapt --harness <claude|codex> [--check]` run from a project (roots
differ) now performs the full integration. `--contract <framework|project>` stays the print-only
diagnostic. `--check` covers the partial-file deliveries per §1. Usage text updated via the Phase 14
dispatch table (no hand-written `USAGE_*`).

## Acceptance (maps to the ROADMAP "Verify" bullets)

- **AC-1 (append-only).** Fixture project with a pre-existing `CLAUDE.md` (user content): one
  `adapt --harness claude` appends exactly the import line, leaving prior bytes intact; a second run
  is a no-op; `--check` exits `0`.
- **AC-2 (create-if-missing).** Fixture with no `CLAUDE.md`: file is created containing only the
  import line.
- **AC-3 (codex round-trip).** codex `AGENTS.md` managed block: edit inside the block → re-run
  restores it; edit outside the block → preserved; `--check` flags an out-of-date block.
- **AC-4 (no clobber of settings).** Fixture with a pre-existing `.claude/settings.json` carrying a
  user key (`model`): after adapt, the user key survives and `env.GATEKEEPER_BIN` +`hooks` are
  present; `--check` does not report the user key as drift.
- **AC-5 (GATEKEEPER_BIN bare invocation).** `env.GATEKEEPER_BIN` = `<framework>/bin/gatekeeper`;
  documented so a session's `gatekeeper check …` resolves with no PATH step (integration-asserted by
  reading the value; live-session proof is Phase 12).
- **AC-6 (scaffold).** The five `.claude/topology/*` dirs exist after one run.
- **AC-7 (bare-stub instruction).** Rendered project `CONTRACT.md` contains the first-session
  gate-shaped instruction; framework `AGENTS.md` regenerates byte-identically to
  `adapt --contract framework` (Phase 10 invariant preserved).
- **AC-8 (fail-closed managed block).** Malformed block (begin, no end) → exit `2` naming the file.
