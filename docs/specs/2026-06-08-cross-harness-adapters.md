# Design: Cross-harness adapters (Phase 4)

- **Date:** 2026-06-08
- **Feature slug:** cross-harness-adapters
- **Status:** approved (authorized as the Phase 4 build; grounded by
  [research](../research/2026-06-08-cross-harness-adapters.md) and
  [ADR-0008](../adr/0008-cross-harness-adapter-mappings.md))
- **Roadmap:** [Phase 4](../ROADMAP.md#phase-4--cross-harness-adapters)

## Goal

Native Codex, Cursor, and OpenCode support **generated** from the one Markdown source (`AGENTS.md` +
`skills/` + `instincts/`), per [ADR-0003](../adr/0003-one-markdown-source-per-harness-adapters.md).
Surface: `gatekeeper adapt --harness {codex|cursor|opencode|claude}`. Outputs are build artifacts,
never hand-edited.

## Shape

A new `gatekeeper/src/adapt.rs` module. Generation is **pure**: each harness has a builder
`fn(root) -> Result<Vec<GenFile>, String>`, where `GenFile { rel_path, contents }`. All I/O is funneled
through one `apply_or_check`:

- **write** (default): create parent dirs, write each file, print `wrote <rel_path>`.
- **`--check`**: re-render in memory, diff against disk; exit `0` if every file is byte-identical,
  `1` if any is missing or drifted (the idempotency gate), writing nothing.

Sources are read with std + the loader already in `instinct.rs`. A small public accessor
`instinct::instincts_for_adapt(root) -> Result<Vec<(id, body)>, String>` is added so the adapters reuse
the one frontmatter parser (no second copy). Skills are read by a local `read_skill` (frontmatter
`name`/`description` + Markdown body + the raw file for verbatim copy), sorted by `name`. The skill
*name* is the frontmatter `name` (so `skills/_getting-started/` → `getting-started`), not the dir.

`AGENTS.md` is required for every harness (it is the contract); its absence is an `exit 2` error with a
clear message.

## Per-harness mapping (the "templates")

### `codex` → `.codex/config.toml`
One project-safe, strict-config-validated key plus a generated-by header:
```toml
# Generated by `gatekeeper adapt --harness codex` — do not edit (regenerate to update).
# Topology's operating contract lives in AGENTS.md, which Codex auto-discovers as project
# instructions. project_doc_max_bytes is raised so the full contract is ingested as it grows.
# No model/sandbox/approval defaults are set here (your ~/.codex/config.toml wins); project-local
# config may not carry credential/provider/profile keys (Codex strips them).
project_doc_max_bytes = 1048576
```
Codex reaches the contract (and via it, `skills/`) through `AGENTS.md`; no profiles (denylisted), no
skills copy.

### `cursor` → `.cursor/rules/*.mdc`
- `agents-contract.mdc` — `alwaysApply: true`, body = `AGENTS.md` (Cursor can't read it natively).
- `instincts.mdc` — `alwaysApply: true`, body = `- [id] body` per instinct (**instincts → Always mode**).
- `skill-<name>.mdc` per skill — `alwaysApply: false`, `description: "<skill description>"`, **no
  `globs`** (Agent Requested — the closest primitive to keyword routing), body = the skill's Markdown.

### `opencode` → `opencode.json` + `.opencode/`
- `opencode.json`: `{ "$schema": "https://opencode.ai/config.json", "instructions": ["AGENTS.md",
  ".opencode/instincts.md"] }` (serialized with `serde_json`).
- `.opencode/instincts.md`: rendered always-on instincts.
- `.opencode/skills/<name>/SKILL.md`: verbatim copy of each `skills/*/SKILL.md`.

### `claude` → `.claude/settings.json`
The source-native harness; adapt makes its install config a generated artifact too — the hooks block
(`UserPromptSubmit` = `<root>/hooks/skill-activation.sh`; `PreToolUse` on `Bash|Write|Edit|MultiEdit`
= `<root>/hooks/security-scan.sh`, timeout 30) install.sh otherwise hand-prints.

## Acceptance criteria (checked in the verify note)

1. `gatekeeper adapt --harness codex` writes `.codex/config.toml`; the file **loads** under
   `codex exec --strict-config --skip-git-repo-check` (no schema rejection), and contains none of the
   denylisted keys (`profile`/`profiles`/`model_provider`/`notify`).
2. `gatekeeper adapt --harness cursor` writes an `instincts.mdc` with `alwaysApply: true`, an
   `agents-contract.mdc` carrying the contract, and a `skill-<name>.mdc` per skill with
   `alwaysApply: false` + a `description` and **no** `globs`.
3. `gatekeeper adapt --harness opencode` writes a valid-JSON `opencode.json` with the schema URL and an
   `instructions` array including `AGENTS.md`, plus `.opencode/skills/<name>/SKILL.md` byte-equal to the
   source and an `.opencode/instincts.md`.
4. `gatekeeper adapt --harness claude` writes a valid-JSON `.claude/settings.json` wiring both hooks.
5. Re-running any harness then `--check` exits `0` (idempotent); mutating a generated file makes
   `--check` exit `1`.
6. An unknown `--harness`, a missing `--harness`, or a missing `AGENTS.md` exits `2` with a clear
   message; the existing suite stays green and `clippy -D warnings` / `fmt --check` are clean.

## Non-goals (this phase)

- Wiring `gatekeeper scan` as a Codex/OpenCode lifecycle hook (the security floor in other harnesses) —
  noted as future work in ADR-0008; out of scope to keep the diff surgical ([[surgical-changes-only]]).
- Auto-running `adapt` from `install.sh` (it stays a printed, opt-in step, so install never clobbers a
  user's existing `.claude/settings.json`).
- External template files / a templating engine (builders in `adapt.rs` are the templates).
