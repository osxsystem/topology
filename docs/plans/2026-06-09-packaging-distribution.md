## Conventions for every task

- **No new runtime dependency.** `[dependencies]` stays `regex`/`serde`/`serde_json`/`toml`; this feature
  does not add a crate. `--version` uses the built-in `env!("CARGO_PKG_VERSION")`; `doctor` and
  `check docs` reuse the existing scan/instinct/skill loaders and `std`. CI **tool** installs
  (`just`, `shellcheck`, `typos`, `lychee`, `cargo-deny`) are workflow steps, not crate deps —
  `Cargo.lock`'s runtime graph stays byte-identical (ADR-0010 consequences).
- **CI mirrors the justfile; it does not re-spell the gate.** Workflows invoke `just check` / `just deny`
  / `just links` and `gatekeeper check docs` — the same recipes the human runs (ADR-0010 §3). A workflow
  that re-types `cargo clippy …` instead of calling the recipe is wrong.
- **The binary is external to the plugin (system-PATH, ADR-0010 §1).** Plugin hooks call `gatekeeper` via
  `PATH` or `$GATEKEEPER_BIN`; nothing is bundled in a plugin `bin/`. Bundled hook *scripts* are referenced
  with `${CLAUDE_PLUGIN_ROOT}`.
- **Version in lockstep.** `plugin.json`'s `version`, `Cargo.toml`'s `version`, and any release tag must
  match; the release workflow asserts it (ADR-0010 §2). Touching one means touching the others.
- **Manifests are hand-authored committed source** (ADR-0010 §5) — not generated by `adapt`.
- **Tests are the per-task gate.** Each task ends green: `cd gatekeeper && cargo test <filter>` for Rust;
  `just <recipe>` or a parse/field assertion for YAML/JSON/docs. `cargo clippy --all-targets -- -D
  warnings` and `cargo fmt --check` are enforced once, in the verify task.
- **Test style:** in-module `#[cfg(test)]` for pure functions; `std::process::Command` +
  `env!("CARGO_BIN_EXE_gatekeeper")` over a scratch framework root for CLI tests (mirrors
  `tests/cli_check.rs`/`cli_adapt.rs`). No `assert_cmd`/`predicates`.
- **Self-protection (expected, not a blocker).** Editing `main.rs`, `scan.rs`, `security/rules.toml`,
  `AGENTS.md`, `scripts/install.sh`, `Cargo.toml`, hook scripts may touch protected paths — land them as
  discrete, reviewable commits. New files (`.github/`, `.claude-plugin/`, `docs/`, plugin README) are not
  protected.
- **Shared-file ordering.** Tasks 1, 2, 3 all edit `main.rs` (dispatch + `cmd_check`) — run them serially
  (or as one agent), never as parallel writers on the same file. The YAML/JSON/doc tasks (5, 6, 7, 8) edit
  disjoint files and may be authored in parallel, committed serially by the main loop (the Phase-5
  parallel-batch discipline).
