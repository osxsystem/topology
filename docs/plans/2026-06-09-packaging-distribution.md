## Conventions for every task

- **No new runtime dependency.** `[dependencies]` stays `regex`/`serde`/`serde_json`/`toml`; this feature
  does not add a crate. `--version` uses the built-in `env!("CARGO_PKG_VERSION")`; `doctor` and
  `check docs` reuse the existing scan/instinct/skill loaders and `std`. CI **tool** installs
  (`just`, `shellcheck`, `typos`, `lychee`, `cargo-deny`) are workflow steps, not crate deps —
  `Cargo.lock`'s runtime graph stays byte-identical (ADR-0010 consequences).
- **CI mirrors the justfile; it does not re-spell the gate.** Workflows invoke `just check` / `just deny`
  / `just links` and `gatekeeper check docs` — the same recipes the human runs (ADR-0010 §3). A workflow
  that re-types `cargo clippy …` instead of calling the recipe is wrong.
- **The binary is external to the plugin (system-PATH, ADR-0010 §1).** Plugin hooks call `gatekeeper` via
  `$GATEKEEPER_BIN` (a **new** override — neither hook reads it today) → `PATH`; nothing is bundled in a
  plugin `bin/`. Bundled hook *scripts* are referenced with `${CLAUDE_PLUGIN_ROOT}`.
- **Hook fail policy is split and must be preserved (`[rev:codex-2026-06-09]`, ADR-0010 §1).** Missing
  binary → **PreToolUse `scan` fails closed** (emit `deny`, `security-scan.sh:4,25,32`); **UserPromptSubmit
  `activate` fails open** (advisory + `exit 0`, `skill-activation.sh:23,27`). Do not "simplify" either to
  match the other. Resolution transparency lives in `doctor`, not the hooks — hooks stay silent on allow
  (`security-scan.sh:28-30`).
- **Version in lockstep.** `plugin.json`'s `version`, `Cargo.toml`'s `version`, and any release tag must
  match; the release workflow asserts it (ADR-0010 §2). Touching one means touching the others.
- **Manifests are hand-authored committed source** (ADR-0010 §5) — not generated by `adapt`.
- **Tests are the per-task gate.** Each task ends green: `cd gatekeeper && cargo test <filter>` for Rust;
  `just <recipe>` or a parse/field assertion for YAML/JSON/docs. `cargo clippy --all-targets -- -D
  warnings` and `cargo fmt --check` are enforced once, in the verify task.
- **Test style:** in-module `#[cfg(test)]` for pure functions; `std::process::Command` +
  `env!("CARGO_BIN_EXE_gatekeeper")` over a scratch framework root for CLI tests (mirrors
  `tests/cli_check.rs`/`cli_adapt.rs`). No `assert_cmd`/`predicates`.
- **Self-protection (expected, not a blocker).** Editing `main.rs`, `scan.rs`, `security/rules.toml`,
  `AGENTS.md`, `scripts/install.sh`, `Cargo.toml`, hook scripts may touch protected paths — land them as
  discrete, reviewable commits. New files (`.github/`, `.claude-plugin/`, `docs/`, plugin README) are not
  protected.
- **Shared-file ordering.** Tasks 1, 2, 3 all edit `main.rs` (dispatch + `cmd_check`), and Task 1 adds
  `version.rs` + a `scan.rs` accessor that Task 2 then reads — run 1→2→3 serially (or as one agent), never
  as parallel writers on the same file. The YAML/JSON tasks (5, 6) edit disjoint files and may be authored
  in parallel. **Two cross-task dependencies introduced by the revision (`[rev:codex-2026-06-09]`):**
  (a) `README.md` is edited by Task 3 (reconcile "static binary"/phantom) **and** Task 8 (plugin section) —
  commit serially, Task 8 last; (b) Task 3's README phantom-manifest fix depends on **Task 7** creating
  `.claude-plugin/plugin.json`, so run **Task 7 before** Task 3's README change (or land that one README
  hunk with Task 7/8). Sequence the binary-dependent doc fixes after the code that makes them true.

## Files (key signatures)

```rust
// version.rs (new, tiny) — the one public seam for tool + schema version ([rev:codex-2026-06-09]).
// --version and doctor depend on THIS, not the private scan::SCHEMA_VERSION. (check docs is NOT a consumer.)
pub fn tool() -> &'static str { env!("CARGO_PKG_VERSION") }
pub fn rules_schema() -> u32 { scan::schema_version() }   // scan exposes a pub fn; const stays private

// main.rs — top-level dispatch (before the --help|-h|None arm)
Some("--version") | Some("-V") => { println!("gatekeeper {} (rules schema v{})",
    version::tool(), version::rules_schema()); 0 }
Some("doctor") => doctor::cmd_doctor(&framework_root()),     // read-only health probes; 0 healthy / 1 fault

// main.rs — cmd_check gains an unfeatured arm
"docs" => check_docs(root),    // docs-coverage lint: skills frontmatter, ADR index, ROADMAP evidence paths

// doctor.rs (new, small) — probes over existing loaders; prints one line per probe, writes nothing.
// First probe = resolution transparency: current_exe() + version::tool(), and how a `gatekeeper` would
// resolve for hooks ($GATEKEEPER_BIN → PATH → repo). ADR-0010 §1: doctor carries this, hooks stay silent.
pub fn cmd_doctor(root: &Path) -> i32;

// check_docs (in main.rs or a small docs.rs) — three rules, all satisfiable on this tree post-fix:
//  R1 every skills/*/SKILL.md parses (skill loader)
//  R2 every docs/adr/00NN-*.md (not README) is linked from docs/adr/README.md
//  R3 every docs/verify/<f>.md path referenced in docs/ROADMAP.md exists on disk
//      (Phase 0 references none → exempt; these prose pointers are NOT markdown links, so lychee misses them)
```

### Task 7: Claude Code plugin manifest + bundled hook wiring
- **File(s):** `.claude-plugin/plugin.json` (new), `hooks/hooks.json` (new), the hook scripts under
  `hooks/` (binary resolution). No file *moves*: `security/rules.toml`, `hooks/skill-rules.json`,

- **Change (a):** `.claude-plugin/plugin.json` — required `name: "topology"` + `version` equal to
  `Cargo.toml`'s, `description`, `author.name`, `repository`, `license`, `homepage`; `hooks` →
  `"./hooks/hooks.json"`; skills resolve from the existing root `skills/`. **The binary reads its data
  relative to `framework_root()` (`main.rs:102`, walks up to the nearest `skills/`) and the hooks
  `cd "$ROOT"` → `${CLAUDE_PLUGIN_ROOT}`, so the plugin root must also carry `security/rules.toml`,
  `hooks/skill-rules.json`, and `instincts/` — without `rules.toml` the fail-closed `scan` hook denies every tool call.**
- **Change (b):** `hooks/hooks.json` — declare the `UserPromptSubmit` + `PreToolUse` handlers as
  `"${CLAUDE_PLUGIN_ROOT}/hooks/<script>.sh"` commands.
- **Change (c) — preserve the split fail policy (`[rev:codex-2026-06-09]`, ADR-0010 §1):** add a `$GATEKEEPER_BIN`
  branch (a **new** override — neither hook reads it today) ahead of each hook's existing resolution order
  (`security-scan.sh` keeps repo-built→PATH; `skill-activation.sh` keeps PATH→repo-built). When the binary
  is absent, **do not change the existing behaviour**: `security-scan.sh` (PreToolUse) stays **fail-closed**
  — emits a `deny` naming the fix (`:25`); `skill-activation.sh` (UserPromptSubmit) stays **fail-open** —
  advisory line + `exit 0` (`:23`). Both stay silent on the happy path. Keep `shellcheck` clean.
- **Change (d) — resolve the framework root via `${CLAUDE_PLUGIN_ROOT}` (ADR-0010 §1, spec §5).** Both hooks
  derive `ROOT` from `BASH_SOURCE` today (`ROOT="$(dirname "$HOOK_DIR")"` — `security-scan.sh:9`,
  `skill-activation.sh:13`). Claude Code exports `CLAUDE_PLUGIN_ROOT` when it loads the plugin, so prefer it
  and fall back to the `BASH_SOURCE` derivation for local-dev wiring (`install.sh` / `adapt --harness claude`):
  `ROOT="${CLAUDE_PLUGIN_ROOT:-$(dirname "$HOOK_DIR")}"`. This makes the docs' "resolution via
  `${CLAUDE_PLUGIN_ROOT}`" literally true and keeps the subsequent `cd "$ROOT"` (so `framework_root()` lands on
  the bundled `skills/`/`security/`/`instincts/`) correct in both the plugin and local-dev contexts. No
  behaviour change when the var is unset; the fallback is a plain parameter expansion (`shellcheck`-clean).
- **Test:** `plugin.json` and `hooks/hooks.json` are valid JSON (parse them); `plugin.json`'s `version`
  equals `Cargo.toml`'s; `hooks.json` commands reference `${CLAUDE_PLUGIN_ROOT}`; the plugin root carries `security/rules.toml`,
  `hooks/skill-rules.json`, `instincts/`, and `skills/` (the data `framework_root()` resolves); **two** no-binary runs
  (empty `PATH`, unset `GATEKEEPER_BIN`): `security-scan.sh` emits a `deny` JSON + `exit 0` (fail-closed),

  behaves the same; a `CLAUDE_PLUGIN_ROOT=<scratch root containing skills/>` run resolves the framework root to
  that scratch dir (data read from there), and with the var unset the hook falls back to the repo root;
  `shellcheck hooks/*.sh` clean. `claude plugin validate .` if the CLI is present.
- **Commit:** `feat(plugin): Claude Code plugin manifest + bundled hook wiring (PATH binary)`
